# M1.5 Staffing decisions

**Goal:** a visitor sees one memorable decision within ~20 seconds: dragging the start date two weeks later closes Atlas's Backend gap, and the verdict line says so with numbers.
**Time box:** 2 weekends. **Depends on:** M1 merged (canvas, CapacityTimeline, approve transaction, per-visitor sandbox).
**Spec:** design.md "E1 Scenarios", "E4 Share snapshots", "/autoplan #2" Phases 2-3.5.

## Scope
- One fork against the baseline: current team (A) vs draft (B), React state only, `beforeunload` warning.
- Start-date scrubber: range `max(today, start)` .. +6 weeks, keeps duration, disabled for started projects; arrows = 1 day, PageUp/PageDown = 1 week; `aria-valuetext`.
- Verdict as the goal line: "Draft B vs A: start +2 wk -> Backend 100%, 0 overbooked days, 1 slot open", Plex Mono numbers, `aria-live` on settle.
- Atomic commit `POST /api/projects/:id/scenarios/commit`: moves project dates via the date-edit clamp when the start changed, then creates all proposals; all-or-nothing.
- Server share snapshots `POST /api/snapshots`, `GET /api/snapshots/:id`, page `/s/:id`.
- "Start over" button (new sandbox).
- Seeded Atlas state where a 2-week scrub closes the Backend gap; coach-mark 1 points at the scrubber.

## Out of scope
Tabs A/B/C, undo, keyboard shortcuts, capacity breakdown, copy as Markdown, counterfactuals (polish bucket).

## Tasks (in order)
1. **domain:** `coverage()`; `compareScenarios(a, b)` -> `{coverage, overbookedPersonDays, startDelayDays, slotsOpen}`; scrub-range helpers taking `today` as a parameter. Table tests + property test.
2. **api:** candidates endpoint accepts `?start=` (validated), returns timelines for W ∪ scrub range (cap 60 candidates); per-date cache invalidated on any mutation.
3. **api:** scenarios/commit in one `withTransaction`: date-edit clamp + overbook recheck if start moved; per-draft duplicate-user and `NO_APPROVER` checks; slot counts with session reads; `touchProject` once; unique partial index `{orgId, projectId, userId}` for non-terminal statuses. Errors carry `details.slotRoleId`.
4. **api:** snapshots: client sends draft slots only; server rebuilds timelines + verdict; zod, <= 64KB, rate-limited; `orgId`, `isDemo`, `expiresAt` (demo 30d, real 90d); GET checks `expiresAt > now`; demo public, real orgs via `can(actor,'viewSnapshot')`.
5. **web:** control row (fork button, scrubber), verdict line, live availability chips while scrubbing, reorder on settle with 240ms FLIP, "re-ranking…" state, mobile pinned scrubber with 44px thumb.
6. **web:** commit flow (spinner, "3 proposals sent", committed draft becomes A), share flow ("Link copied"), `/s/:id` page (header "Snapshot · date · read-only", CTA, expired state), "Start over".
7. **seed + design:** Atlas scenario seed; DESIGN.md additions (control row, verdict line, slider tokens).
8. **e2e:** scrub -> verdict flips -> commit; share -> open in a fresh context; keyboard-only scrub; frozen clock.
9. Re-record the README GIF.

## Tests
compareScenarios/coverage table tests; scrub-range property test; commit: rollback, in-txn slot count, duplicate user, moved start; snapshots: forged content impossible, size cap, demo public, employee 403, expired 404 incl. TTL lag; e2e as in task 8.

## Done when
On the deployed demo, a first-time visitor can follow the coach-mark, scrub, see the verdict change, and commit, in under a minute; all tests green; GIF updated.

## Risks
Scrub payload size (cap candidates); FLIP jank on low-end devices (respect reduced motion); clock-dependent tests (inject `today`).
