# M1.75 AI-drafted teams

**Goal:** "AI drafts a team, the engine proves it, the scrubber shows when it works" as one demo loop.
**Depends on:** M1.5. **Spec:** design.md "AI-01 (LLM drafts a team, engine validates)", Phase 2 error registry (`AI_UNAVAILABLE`).

## Scope
- `POST /api/ai/search` with the PM's plain-language request.
- Prompt includes the org vocabulary and pseudonymous candidate summaries (`c1..cN`: skills, levels, availability windows); no names or emails.
- JSON schema output `{assignments: [{candidateRef, slotRoleId, hoursPerDay, from}], rationale: string[]}`; zod-validated; unknown refs dropped.
- Server maps refs to users, runs every placement through `withProposal`, slot limits and approver checks; returns per-slot verdicts.
- Canvas shows the draft as ghost placements in draft B with per-slot fits/conflict and the rationale; PM accepts slots individually or commits the whole draft via scenarios/commit.
- `LLM_API_KEY` optional: panel disabled with "set LLM_API_KEY to enable"; fixture-backed fake provider for CI.
- Per-session rate limit; raw JSON logged to the browser console (SRS).

## Tasks
1. Provider interface + real provider + fake provider (fixtures).
2. Prompt builder (pseudonymization) + output schema + validation.
3. Validation pipeline reusing domain checks; per-slot verdicts.
4. Web panel: input, loading, ghost placements, rationale, errors (`AI_UNAVAILABLE`, `RATE_LIMITED`).
5. Eval set: ~20 golden prompts scored by "fraction of slots that pass validation" and "required-skill coverage"; runs on main nightly with the real key, on PRs with the fake provider.

## Tests
Pseudonymization (no PII in prompt); malformed/empty/refusal/timeout -> `AI_UNAVAILABLE` with manual staffing unaffected; unknown refs dropped; validation verdicts match manual drops; e2e with fake provider.

## Done when
A PM types "2 backend devs and a QA from March" and sees a validated draft on the canvas; evals recorded; works with no key (disabled state).

## Risks
Cost abuse (rate limit); prompt injection via request text (schema-constrained output, ids validated, no tools).

## Implementation notes (eng review before AI-01, 2026-11-03)
docs/design.md asked for a fresh /plan-eng-review before AI-01. Checked against the merged M1.5 code; decisions below.

1. **Premise 3 drift fixed.** The premise said the LLM "never picks people"; the gate-chosen AI-01 has it draft from the engine's top-ranked candidates. Premise 3 now says exactly that (pseudonymous, engine-validated, PM commits). The stale TODOS.md "filter JSON" eval entry is replaced by task 5 here.
2. **Provider.** Anthropic Messages API via `@anthropic-ai/sdk`, model `claude-opus-5-5` (override `LLM_MODEL`), effort `low` (a short selection task; latency matters), structured output with `betaZodOutputFormat` (schema-constrained JSON, parsed and re-validated with zod), `max_tokens` 4096, 30 s timeout, 1 retry. Server-side refusal fallbacks on (`fallbacks: "default"`); a refusal that survives them is `AI_UNAVAILABLE`.
3. **One start, not per-person `from`.** The M1.5 draft has a single start, so the output schema has an optional top-level `start` (clamped into the scrub range; ignored once the project has started) instead of a `from` per assignment. "From March" moves the scrubber; per-person starts stay a manual edit.
4. **Pseudonymization.** Candidates are `c1..cN` (top 20 by the engine, ranked at the project start with partial and rolling-off people included): title, target-skill levels, hours free, available-from date. No names, emails or ids. The ref map lives only in the request. Role slots are sent with their real ids (not personal data) and validated.
5. **Validation reuses the domain.** Each assignment: unknown ref or slot → dropped (counted); same person twice, already on the team, slot full (team + earlier picks), no approver → rejected with that reason; otherwise `withProposal` over the scenario window → fits, or conflict with date/used/max hours. The canvas never trusts the model: rejected picks don't enter the draft.
6. **Cost and abuse.** Per-session limit 5 requests/min and a process-wide daily cap (default 300, `LLM_DAILY_CAP`); request text ≤ 500 chars, inside a delimited user turn; no tools. Prompt injection can at worst choose different candidates from the same validated pool.
7. **Providers.** `LLM_PROVIDER=fake` selects a deterministic fixture provider (CI unit/API tests and e2e); unset key and no fake → `GET /api/ai/status` says disabled and the panel shows "set LLM_API_KEY to enable".
8. **Evals.** `apps/api/eval/ai-drafts.ts`: 20 prompts on the Atlas seed, scored by validated-slot fraction and required-skill coverage of the resulting draft; runs on PRs with the fake provider (as a unit test, thresholds checked), and `pnpm eval:ai` with a real key (nightly workflow, skipped when the secret is absent).
